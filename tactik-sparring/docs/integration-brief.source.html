PurposeWhat this document covers

Following our call on 21 September, this sets out what the TACTIK platform is, what it produces, where an implementation partner would work, and what a first scoped engagement could look like.

It is written for an engineering reader. It describes interfaces, deployment surfaces and acceptance criteria rather than product positioning. Where the platform is incomplete, that is stated plainly, because a scope you cannot quote is of no use to either of us.

Scope of disclosure

This document covers the integration perimeter: interfaces, data contracts, deployment surfaces, and the output artifact. It does not cover the reasoning layer, the behavioural profile authoring method, the adjudication logic or the scoring model. That boundary is the one already reflected in the mutual NDA, and it is not a negotiating posture: none of it is required to scope, quote or deliver the work described in Section 5.

Section 02What it produces

The output is the product. Everything else is machinery that exists to generate it reliably.

The attached case file is a real artifact from a real session, not a mock-up. It is the specification target: whatever is built must produce this, reliably, at acceptable latency and cost.

ComponentContentWhy it matters for integration
Audit headerledger UUID, trace id, timestamp, transcript hash, engine version provenanceEvery figure must be traceable to a specific engine build. Version provenance distinguishes the build that ran the session from the build that compiled the file.
In-turn ledgerappend-only, turn-indexedWritten during the session, not reconstructed afterwards. This is the hardest non-functional requirement in the system.
Scored axessix, one excluded by designFive score the participant. The sixth measures whether the modelled counterparty stayed true to its profile, and is deliberately kept out of the composite.
Forensic auditper-turn, quotation-backedNo scored row exists without a verbatim quotation behind it.
Rendered filePDF, six pagesServer-side rendering pipeline. Charts are generated from ledger rows, never hand-placed.

Two properties are non-negotiable and shape the architecture more than anything else. The ledger is written in-turn, because a record reconstructed after the fact is a narrative rather than evidence. And unmeasured never reads as clean: an axis the system could not observe is reported as undetermined and excluded from the composite rather than scored as zero.

Section 04Integration perimeter

What a partner works on, and what stays inside TACTIK. The boundary is drawn on necessity, not secrecy.

In scope for a partner

  • Credential brokering and session lifecycle. Edge function issuing ephemeral tokens; hard duration caps; teardown on unmount, timeout and absence; one concurrent metered session per user.
  • Video layer integration. WebRTC session establishment, dual-track binding, provider abstraction behind the existing interface, mock provider for zero-cost testing.
  • Conferencing surfaces. Zoom, Teams and Meet participation so observers can watch a live session without the participant screen-sharing.
  • Observability. Latency instrumentation per pipeline stage, inference spend telemetry per tenant, alerting on cost and on session leakage.
  • Persistence and tenancy. Ephemeral persistence for evaluator sessions, row-level security policies, retention and deletion.
  • Rendering pipeline. Hardening the server-side case file generation, canonical hashing of the source transcript, deterministic output.

Outside the perimeter

The reasoning layer, the behavioural profile authoring method, the adjudication logic, the scoring model, the prompt architecture and the internals of the sealing pipeline remain with TACTIK and are not licensed. This is already reflected in the mutual NDA received from your side, which preserves TACTIK intellectual property, prohibits reverse engineering and grants no license.

This boundary is practical rather than defensive. Every item in the in-scope list can be specified, built, tested and accepted without reference to any of it. A partner integrates against declared interfaces and measurable acceptance criteria.

Section 05Proposed first engagement

Narrow, fixed price, objectively testable. Designed so both sides learn whether this works before either commits further.

DeliverableAcceptance criterion
Credential brokerNo third-party key present in the shipped browser bundle, verified by inspection. Client receives a room reference and nothing else.
Deterministic teardownSessions terminate on component unmount, on duration cap and on participant absence. Demonstrated by a test that abandons a session and shows billing stops.
Latency instrumentationPer-stage timings recorded and queryable. A 95th-percentile figure reportable for any date range.
Ephemeral evaluator persistenceA guest session produces a retrievable ledger and case file, deleted automatically after a defined window.
One conferencing surfaceObservers join a live session through a single named platform and see the session feed as a participant.

Indicative duration four to six weeks. Fixed price against these criteria rather than time and materials. If the engagement works, the natural follow-on is the live video latency work, which is the gate on the whole video modality and is better attempted once the cost controls above are in place.
